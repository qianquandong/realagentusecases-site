## 速读结论

- 在 Claude.ai（Pro 档）+ Gmail Connector 上跑一个邮箱整理 agent——零代码、零 API key。
- 读最近 24 小时的邮件，归四类，输出一份 P0/P1/P2 的 to-do，每条带原邮件链接。
- 搭起来约 20 分钟，月费 $20（Claude Pro）。每天跑约 40 秒，手机上手动触发。
- 跑了两周；每天早上能省下大概 25 分钟"看邮箱看到走神"的时间。
- 五处 `[方括号]` 需要自己改——角色、老板、项目、当前重点、永远跳过的发件人。

## 这段 prompt 在做什么

- 把你的 Gmail 收件箱归四类：今天必办 / 本周跟进 / FYI / 跳过。
- 输出一份按优先级排好的 to-do：🔴 P0（紧急+重要）、🟡 P1（重要）、🟢 P2（可选）。
- 每条 P0/P1 都包含：邮件主题、具体动作、时间窗口、预计耗时。
- 末尾附 `Sources:` 段——每个优先级判断都有一条回到原邮件的链接。

## 适合谁

- 每天靠 Gmail 开工、头一个小时浪费在收件箱里的人。
- 邮件确实决定一天的角色：分析师、经理、运营、founder、HR / 招聘。
- **不适合**——收件箱本来就空、或者没订 Claude Pro + 没装 Gmail Connector 的人。

## 完整 prompt

```text
你的任务：整理用户的 Gmail 收件箱，并基于邮件内容生成今天的优先级
待办清单。请用中文回复。

## 执行步骤

1. 拉取最近邮件
   - 使用 Gmail MCP 工具 search_threads 搜索最近 24 小时的邮件
     （query 参考：newer_than:1d 或 is:unread newer_than:2d）。
   - 如果未读邮件较多，再补充一次 is:important newer_than:3d 的
     搜索，确保不漏掉重要但已读的线程。
   - 对关键邮件用 get_thread 获取完整内容以便准确判断。

2. 分类与归纳
   将邮件归入以下四类，并简要说明每封邮件的发件人、主题和核心诉求：
   - 需要今天回复或处理的（含明确截止日期、老板/客户催办、面试/
     会议确认等）
   - 需要本周内跟进的
   - 仅供参考/知会（newsletter、通知、回执）
   - 可直接归档或忽略的（推广、订阅、垃圾）

3. 生成优先级 Todo List
   按以下三级优先级输出今天的待办，每条包含：来源邮件主题、具体动作、
   建议时间窗口（上午/下午/晚上）、预计耗时。
   - 🔴 P0 紧急且重要（必须今天完成）
   - 🟡 P1 重要但不紧急（今天推进）
   - 🟢 P2 可选/低优先级（有空再做）

4. 输出格式
   用中文，以清晰的 Markdown 结构呈现。开头给出一句话总结
   （例如"今天有 3 件必办、5 件待跟进"），然后给出分类邮件摘要，
   最后给出 Todo List。末尾附上 "Sources:" 部分，使用 Gmail
   链接格式 [主题](https://mail.google.com/mail/u/0/#inbox/THREAD_ID)
   引用引用过的邮件线程。

## 约束
- 不要自动回复或删除邮件，只做整理和建议。
- 如果 Gmail 连接器未授权或无法访问，明确告知用户并提示去授权。
- 如果当天邮件极少（<3 封），直接简要汇报"今日邮箱清净"并给出
  可选事项即可，不要为了凑数编造任务。
- 保持简洁，避免冗长解释。

## 我的背景（这一段务必改成你自己的）
- 角色：[你的岗位，如"德州仪器工业工程师，2026 年 4 月转业务规划"]
- 老板：[名字 + 邮箱]
- 活跃项目：[项目名 — 涉及这些的邮件自动升 P0/P1]
- 当前重点：[这个月你在专注什么]
- 永远跳过的发件人：[newsletter@..., notifications@..., 等]
```

## 怎么改成你自己的

prompt 里有五处 `[方括号]`——只有这五处真正要改。结构是通用的；这段 prompt 能不能跑好，全看你这五处填得有多具体。

1. **`[你的岗位...]`**——你的职位和当前重点。要具体。"某 fintech 的资深数据分析师，负责每周 KPI 报表"比"数据分析师"强得多。
2. **`[老板：名字 + 邮箱]`**——你老板的邮箱。agent 靠它识别"老板回复了"这种信号，自动加优先级。
3. **`[活跃项目]`**——手上正在跑的项目名。任何提到这些名字的邮件，自动升到 P0/P1。
4. **`[当前重点]`**——你这个月在专注什么。帮 agent 在"重要的"里挑出"对的那种重要"。
5. **`[永远跳过的发件人]`**——你直接忽略的发件人或域名。这些发件人发的邮件，不管主题写得多吓人，都不能进 P0。

## 常见翻车点

这些都是头两周真踩过的。**改 prompt，别改输出**——每改一次 prompt，明天的 triage 就永久好一点。

- **一封 "thanks" 回复被丢进 P0。** 加规则：单纯确认/致谢的回复永远不能进 P0。
- **一条藏在 12 封回复里的会议确认漏了。** 加规则：超过 5 封回复的线程，必须用 `get_thread` 把全文拉完再判断。
- **Amazon / 快递通知被过度上报。** 把这些发件人加进"汇总专用"清单——只报个总数，不一个一个列。
- **营销邮件的 "Final notice" 被误判成紧急。** 加规则："永远跳过"清单里的发件人，不管标题写得多吓人，都不能进 P0。
- **头 1-7 天会很吵。** 别指望开箱就 90% 准——这个准确率要靠 5-7 天的 prompt 调优才稳得下来。

## FAQ

**这段 prompt 粘到哪儿？**
粘进 Claude 的 Project system prompt，或者作为 Custom Instruction。打开 Claude.ai → Settings → Custom Instructions，或者新建一个 Project，把它放进 Project 的 system prompt 那一栏。

**需要 Claude API key 吗？**
不需要。这段 prompt 整段在 Claude.ai（Pro 档）里跑——零 API、零代码。Gmail Connector 是 Pro 自带的功能，授权一次就行。

**agent 会替我发邮件或删邮件吗？**
不会。约束部分明确禁止。agent 只读取、分类、建议——动作还在你手里。

**能换成 ChatGPT 或 Gemini 吗？**
prompt 的结构可以套，但 Gmail Connector 是 Claude 专属的。ChatGPT 想读 Gmail，得靠自定义 GPT + Zapier，那条路就不再是零代码零 API key 了。

**多久能调到准？**
大概 5-7 天。头一周，预期每天早上加 1-2 条规则。之后会稳定在大约 90% 的优先级判断正确率。

**那天邮件不到 3 封怎么办？**
prompt 明确告诉 agent 直接说"今日邮箱清净"——不要为了凑数编造任务。安静的早上没关系。
